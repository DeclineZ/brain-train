# Game Tracking Handoff

Branch: `feature/analytics`
Split: **Games 01–12 → Ashi**, **Games 13–21 → Timmy**
Target: every game emits a timeline of player actions with millisecond timing, without changing gameplay or scoring.

This document is the full spec. If you hand it to an AI assistant, give it this whole file plus the game folder you are working on, and tell it to follow sections 1–4 exactly before touching section 5.

---

## 0. Why we are doing this

Today each game saves **one row per finished level** in `game_sessions` (score, stars, duration, six domain scores, and a `raw_data` JSON with end-of-level totals). That tells us *how a level ended*, not *how the player got there*.

We want to answer questions like:

- When exactly does the player press each button, and how fast do they react to each stimulus?
- Where in a level do they hesitate, make mistakes, or give up?
- Do they get faster or slower as the level goes on (fatigue, learning)?
- Which specific stimuli, rules or layouts cause errors?
- How does behaviour differ between touch and keyboard, or with sound muted?

Every event must therefore carry **what was on screen**, **what the player did**, **when** (ms since level start), and **whether it was right**.

---

## 1. Ground rules (read before writing any code)

1. **Do not change gameplay, scoring, stars, coins or `raw_data` fields.** Tracking is additive. If a scoring function reads a field, leave that field exactly as it is. The existing `raw_data` payload sent through `onGameOver` must stay byte-for-byte compatible except for the one new field `attempt_id` (section 3.4).
2. **Tracking must never break or slow a game.** Every `track` call is fire-and-forget, wrapped so an exception inside analytics can never throw into game code. No `await` on tracking inside a game loop.
3. **Never log personal data.** No names, emails, birth dates, friend codes, patient IDs, free text the user typed. Game content (card values, words shown, numbers) is fine.
4. **Don't log every frame.** `update()` runs ~60 times a second. Log *changes* (player started steering left, stopped steering) and *decisions*, never per-frame positions.
5. **One event per real thing that happened.** If a click is ignored by the game (board locked, animation running), log it once as `input_ignored` with a reason; don't log it as a normal action.
6. **Tutorial scenes are tracked too**, with `mode: 'tutorial'`. Only do tutorials after the main scene for that game is finished.
7. **Use the shared helper only** (`games/engine/telemetry.ts`). Do not call Supabase or `fetch` from a game.
8. **Keep event names and property names exactly as written in this doc.** If you need a new event or property, add it to section 5 for that game *and* to `lib/analytics/events.ts` in the same commit, and tell the other person.

### 2.2 Client: `lib/analytics/track.ts`

- `track(event: EventName, props?: object, ctx?: { stepId?, gameId?, level?, attemptId?, seq?, tMs? })`
- Queues events in memory, flushes every 5 s, when the queue reaches 50, on `visibilitychange` to hidden, and on `pagehide` (via `navigator.sendBeacon`).
- Posts to `app/api/analytics/route.ts`, which checks the event name against `lib/analytics/events.ts`, adds `user_id` from the session, and inserts.
- Swallows every error. Respects an `analytics_opt_out` flag.

### 2.3 Game helper: `games/engine/telemetry.ts`

This is the only API game code uses.

```ts
import { GameTelemetry } from '@/games/engine/telemetry';

// in create() / init(), once per scene start
this.telemetry = GameTelemetry.forScene(this, { gameId: 'game-01-cardmatch' });

// when the player can actually start interacting (after intro popup / countdown)
this.telemetry.levelStarted({ /* level setup props, see section 5 */ });

// any player action or game decision
this.telemetry.action('card_flipped', { card_index: 3, pair_id: 'cat', seen_before: true });

// when the level ends, right before calling onGameOver
this.telemetry.levelEnded({ outcome: 'success', /* end props */ });
// attempt_id is added to raw_data by the play page; adding it here is optional.
const payload = { ...existingPayload, attempt_id: this.telemetry.attemptId };
```

What the helper does for you:

- Reads `level` from `this.registry.get('level')` and the mode (`normal` / `tutorial`) from the scene key or an explicit option.
- **Attempt id comes from the play page.** The play page creates one `attempt_id` per level mount and puts it in the Phaser registry (`this.registry.get('attemptId')`). The first `levelStarted()` uses that id. If the scene restarts itself without remounting (for example Dream Direct's `R` key), the next `levelStarted()` creates a new UUID and writes it back with `this.registry.set('attemptId', id)`. The play page listens for that change and closes and reopens its app-level attempt. A restart or replay is always a new attempt.
- Adds `seq` and `t_ms` automatically. `t_ms` uses `performance.now()` from `levelStarted()`, **not** Phaser's clock, so it keeps running while the game is paused; pauses are logged as events (section 3.2).
- Adds the common props every event needs: `input_method` (`touch` / `mouse` / `keyboard` / `tilt`, from the last input), `muted` (from `scene.sound.mute`).
- Ignores calls before `levelStarted()` or after `levelEnded()`, and logs one `telemetry_misuse` warning in development.
- Provides `this.telemetry.stimulus(id)` / `this.telemetry.rtFrom(id)` to measure reaction time: call `stimulus('card_7')` when something appears and `rtFrom('card_7')` when the player responds, and it returns ms between them (or `null`).

As built, beyond the plan above:

- Every event also gets `mode` alongside `input_method` and `muted`. `input_method` is `null` until the first tap or key press in the scene.
- Tilt games call `this.telemetry.setInputMethod('tilt')` when tilt input is used; the next tap or key press overrides it.
- `levelEnded()` fills in `actions` (count of `action()` calls), `errors` (count of `action()` calls with `correct: false`) and `duration_ms` (wall time since `levelStarted()`, pauses included). Pass any of them to override, e.g. `duration_ms` for active time. `input_ignored`, pause, time and tutorial-step events are not counted as actions.
- The registry id is used by the first `levelStarted()` in the **game**, not per scene: any later `levelStarted()` (restart, replay, or a second scene such as Taxi Driver's tutorial → game) gets a new id.
- A second `levelStarted()` without `levelEnded()` (restart mid-level) is allowed and simply starts the new attempt.
- `this.telemetry.isActive` is true between `levelStarted()` and `levelEnded()`.
- `rtFrom(id)` doesn't clear the stimulus, so several responses to one stimulus all measure from when it appeared. Calling `stimulus(id)` again resets it. Stimuli are cleared by `levelStarted()`.

```ts
// Reaction time and an ignored tap
this.telemetry.stimulus(`card_${index}`);               // card became tappable
if (this.isLocked) {
  this.telemetry.action('input_ignored', { reason: 'locked', target: card.name });
  return;
}
this.telemetry.action('card_flipped', { card_index: index, rt_ms: this.telemetry.rtFrom(`card_${index}`) });
```

### 2.4 Generic tap capture (all 21 games, no per-game code)

In `components/game/GameCanvas.tsx`, after the game boots, attach one `pointerdown` listener per active scene and one `keydown` listener on the window while the canvas is mounted. Each emits:

`input_raw` → `{ kind: 'pointer' | 'key', x, y, x_pct, y_pct, key, target: gameObject?.name ?? null }`

As built: `x` / `y` are game coordinates (rounded), `x_pct` / `y_pct` are relative to the game size, and `target` is the name of the top game object under the pointer. Key events have `x`, `y`, `x_pct`, `y_pct` and `target` set to `null`, skip auto-repeat, and skip keys typed into form fields. Raw input events carry `attempt_id` but no `seq` / `t_ms` (those belong to the helper's timeline); order them by `occurred_at`. Pointer moves are not logged.

This gives every game a baseline tap timeline on day one. Per-game events in section 5 add the *meaning* (what was tapped and whether it was right). Give interactive game objects a `.setName('...')` where it is cheap, so `target` is readable.

### 2.5 App-level events (not your job in the games)

The play page (`app/play/[gameId]/page.tsx`) and `GameCanvas.tsx` already emit these. **Do not duplicate them inside games:**

`game_page_viewed`, `game_loaded {load_ms}`, `intro_popup_shown`, `intro_popup_closed`, `activity_started` / `activity_ended` (app-level attempt boundaries, including `exited/user_exit` for the home button or leaving mid-level), `result_viewed`, `replay_clicked`, `next_level_clicked`, `previous_level_clicked`, `mute_toggled`, `timeout_popup_shown`, `tutorial_completed`, `error_occurred {error_code: 'result_save_failed'}`.

Renamed from the original plan: `level_quit` → `activity_ended` with `end_reason: 'user_exit'`; `result_screen_shown` → `result_viewed`; `session_save_failed` → `error_occurred`. `timeout_choice` was dropped because the timeout popup auto-continues.

## 3. Events every game must emit

These come from the helper and are the same everywhere.

### 3.1 `level_started`

Call it at the moment the player can first act. For games with an intro popup, that is after `START_LEVEL`. For countdown games, it is when the countdown finishes. Props: whatever describes the level setup (listed per game in section 5) plus:

| prop | type | notes |
|---|---|---|
| `difficulty_multiplier` | number | if the game has one |
| `time_limit_ms` | number \| null | null if untimed |
| `seed` | number \| null | if the level is seeded |

### 3.2 Pause and timeout

| event | when |
|---|---|
| `level_paused` `{reason}` | game freezes for any reason: `'timeout_popup'`, `'hint'`, `'tutorial_popup'`, `'reference'`, `'phase_transition'`, `'powerup_popup'` |
| `level_resumed` `{reason, paused_ms, penalty: boolean}` | game continues |
| `time_warning` `{remaining_ms}` | low-time warning starts (sound or shake) |
| `time_up` `{}` | the game's own timer hits zero (before the popup) |

Games that already handle `resume-game` from `GameCanvas` (Card Match, Billiards, Floating Ball Math and others using `resumeGame(applyPenalty)`) log `level_resumed` with `penalty: applyPenalty` inside that method.

### 3.3 `level_ended`

Call right before `onGameOver(...)`, once per attempt.

| prop | type | notes |
|---|---|---|
| `outcome` | `'success' \| 'fail' \| 'timeout' \| 'game_over'` | |
| `score` | number | same value sent to `onGameOver` |
| `stars` | 0–3 | same value sent to `onGameOver` |
| `duration_ms` | number | active time |
| `actions` | number | count of meaningful actions logged this attempt |
| `errors` | number | count of wrong actions logged this attempt |

### 3.4 `attempt_id` in `raw_data`

The play page already adds `attempt_id` to `raw_data` in `handleGameOver`, using the registry id. It keeps the game's value if the game sets one. Games may add `attempt_id: this.telemetry.attemptId`, but this is optional. It is still the **only** change allowed to the existing payload. It lets us join the event timeline to the `game_sessions` row.

### 3.5 `input_ignored`

`{ reason: 'locked' | 'animating' | 'already_selected' | 'paused' | 'out_of_moves' | 'invalid_target', target }` when the player tries something and the game discards it. These are frustration signals, so log them.

## 4. Conventions

- Event names: `snake_case`, `object_verb` past tense (`card_flipped`, `answer_submitted`).
- Prop names: `snake_case`. Times in **ms** with the `_ms` suffix. Booleans start with `is_` / `was_` or are plain adjectives (`correct`).
- Grid positions: `{ row, col }` zero-based. Screen positions: `x_pct` / `y_pct` (0–1) so different screen sizes compare.
- Reaction time prop is always `rt_ms`: from the moment the relevant stimulus became visible/interactive to the player's input.
- `correct` is always from the game's own rule check; never recompute it in tracking code.
- Don't log large arrays per event. Level setup arrays (e.g. the full sequence) go in `level_started` once.
- Keep props under ~1 KB per event.

## 7. Testing (each game, before marking done)

### 7.1 Regression: scoring must not change

1. Before your change, play one level and copy the `raw_data` the game sends. In dev it is already printed by `hooks/useGameSession.ts` (`[useGameSession] submitSession called`).
2. After your change, play the same level the same way.
3. All existing fields must be identical in shape and still produce the same stars and domain scores. The only new field is `attempt_id`.
4. Run `npm run lint` and `npm run build`.

### 7.2 Events

In dev, `track.ts` should log each event to the console (`[analytics] card_flipped {...}`). Check:

- [ ] `level_started` comes first and `level_ended` last, once each per attempt.
- [ ] Replaying the level produces a **new** `attempt_id` and `seq` restarts at 0.
- [ ] Every ⭐ event in section 5 fires at least once in a normal play-through.
- [ ] `correct` values match what the game showed (green / red feedback).
- [ ] `rt_ms` is plausible (100–10 000 ms for most taps, never negative).
- [ ] No event fires every frame (watch the console while idle for 10 s).
- [ ] Pausing (timeout popup, tab switch) logs `level_paused` / `level_resumed`.
- [ ] Quitting mid-level via the home button still flushes the events already logged (check the network tab for the beacon).
- [ ] Muted vs. unmuted shows in `muted`.
- [ ] Touch and keyboard both work and show the right `input_method` (where the game supports keys).

### 7.3 Database

After a play-through on the dev database:

```sql
select seq, t_ms, event, props
from analytics_events
where attempt_id = '<attempt id from console>'
order by seq;
```

The timeline should read like a replay of what you just did.
